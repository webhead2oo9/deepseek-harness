# Agent Note: 完整请求压缩接纳

Status: implemented

[English](2026-08-17-complete-request-compaction-admission.md) | 中文

## 问题

`agent/pre-step` 中的压力压缩发生在已领取消息批次、运行时上下文、最终请求 header 与活动适配器容量全部出现之前。单条大型传入消息或路由变化因此可能使待发请求从低于配置阈值直接越过活动上下文窗口，而系统没有第二次主动检查。只有适配器把失败规范化时，提供方确认的溢出才能充当兜底。

原生 Codex 还会区分目录中经过调优的默认上下文窗口与可选的更大活动窗口。把默认值当作不可变上限，会阻止显式选择扩展窗口；默认采用目录上限，则会在用户没有表达意图时增加上下文用量。

## 决策

agent loop 会在记录进入步骤的消息、解析 `agent/request`、准备精确适配器注册、记录规范请求 header 与活动容量并冻结完整请求之后，但在适配器流分发之前，派发限定到 agent 的 `agent/request-admission` waterfall。payload 包含不可变请求、活动 `contextWindow`、turn 与 step 坐标、重建次数和 turn signal。

只有持久表层替换推进 `Session.surface.replaceGeneration` 后，接纳 listener 才会返回 `{ kind: 'rebuild' }`。循环会拒绝没有进展的重建，并在八次取得进展的重建后使该轮次失败；它会保留已准备的适配器、调用配置、系统提示词、工具与容量，通过 `Session.deriveMessages()` 重建消息，并再次派发接纳。被丢弃的候选请求不会到达适配器，也不会产生 assistant chunk。该机制把策略保留在插件中，同时维持从日志重建请求的能力。

`dsh-compaction-basic` 拥有主动接纳。它通过 `ctx.tokenMeter` 计量所提供的规范请求 header 与完整当前表层，把策略应用于所提供的活动容量，并在剪枝或摘要替换推进表层后请求重建。它只会跳过携带自身替换 generation 的紧接下一次接纳；任何其他接纳 listener 所做的替换都会在后续接纳中重新计量。它不会再次解析模型元数据。规范提供方溢出继续经由 `agent/request-error` 充当响应式兜底。

原生 Codex 适配器把可识别的 HTTP 与流式上下文窗口失败规范化为 `CONTEXT_WINDOW_EXCEEDED`。可选的 `modelContextWindow` 配置会在不改变默认值的情况下选择活动窗口；模型发现提供的 `max_context_window` 会限制选中的覆盖值、目录默认值或回退值。压缩阈值继续属于压缩策略，而不属于适配器策略。

## 测试

agent-loop 测试固定不可变接纳 payload、由 generation 证明的纯消息重建、单次适配器分发、无进展拒绝与重复进展的重建上限。压缩 listener 顺序测试证明：位于其前后位置的其他 listener 触发重建后，请求都会重新计量；只有压缩自身产生的紧接下一次接纳不会重复压缩。真实循环压缩覆盖从持久历史开始，加入一条使完整请求达到压力条件的进入消息，并证明第一次分发的请求包含检查点而不是已遮蔽历史。现有真实循环溢出测试继续证明抛出式和带内恢复。一个无密钥的组装 headless snapshot 会记录工具续步的 `step/start` 与首个提供方 chunk 之间发生的主动压缩，并证明重建请求能够完成。

Codex 适配器测试固定配置窗口上限处理，以及 HTTP code／type／message、失败／不完整 response 与通用 SSE 溢出的规范分类。类型检查和限定事件生成验证确保每个 agent 事件映射都提供新的限定 resolver。

## 考虑过的替代方案

- **保留 pre-step 压力并依赖溢出恢复**——不予采用，因为提供方可能以不同方式截断、接受或分类超大请求，而且第一次超预算请求已经越过网络边界。
- **在 `agent/pre-step` 内估算已领取批次**——不予采用，因为运行时上下文、最终路由、适配器默认值、工具与容量在该点尚未固定。
- **压缩后重新运行完整请求构建**——不予采用，因为只有持久消息表层发生变化。复用已准备路由可以避免重复请求 middleware 副作用，并让一次尝试始终绑定同一个适配器注册。
- **默认采用 Codex 最大窗口**——不予采用，因为更大窗口是显式的成本与性能选择。除非配置主动选择，否则目录默认值保持活动。

## 后果

每次主动压力决策都会描述原本即将分发的请求，包括刚进入步骤的消息和最终路由容量。成功替换会增加一次本地消息重建和一次接纳过程，但不会产生被丢弃的提供方调用。接纳插件无法在没有持久模型可见进展时重建；即使持续取得进展，同一个待发请求也不能超过固定的八次重建协议上限。

agent loop 增加一个 awaited 扩展点，压缩触发器携带精确的待发请求事实。适配器仍必须继续规范化提供方溢出，以支持响应式恢复。表层压缩依然无法缩减超大的系统／工具 envelope，也不能拆分单条不可分的保留消息。
