# Agent Note: Subagent model routes use persisted named profiles

Status: implemented

[English](2026-08-17-subagent-model-profiles.md) | 中文

## 问题

委派工具可以通过组合中的 `agentOptions` 设置一个子代理模型路由，但通过该工具发起的每次调用都会共用这一条路由。在每次调用中暴露原始提供商和模型标识符虽然灵活，却没有部署方控制的候选列表与说明；为每条路由复制具名工具则会扩大工具目录，并让用户修改必须经过组合编辑。

并非所有子代理后端都控制 LLM 路由。进程内子代理会创建 Harness Agent，因此可以采用提供商和模型选项；Codex 与 Claude Code 等固定外部产品通过自身配置选择模型。通用选择器不能宣称后端实际会忽略的能力。

## 决策

`SubagentRuntime` 拥有 `subagent-model-selection` 设置区段。它将组合默认值与可选设置提供方合并，并发布一个包含 `profiles` 和 `allowDirectModelSelection` 的共享值。每个配置包含面向模型的说明、不透明的提供商/模型对以及可选的子代理系统指令和适配器自有推理强度。Web 的“子代理”设置页面编辑该命名空间，将实时模型与确切路由的推理元数据作为建议，允许手动输入私有、暂时离线或未来提供商的字符串，并提供指令和强度编辑器与紧凑卡片预览。

绑定到具有 `modelRoute` 能力的后端时，`tool-subagent` 实例会暴露已配置的配置名称。共享开关开启后，它还会暴露直接的 `provider` 和 `model` 字段；后端支持时，还会暴露 `reasoning_effort`。一次调用只能选择一个配置或一组完整的直接路由，不能同时选择两者。所选路由只替换 `agentOptions.provider` 与 `agentOptions.model`，其他子代理选项保持不变。配置存在指令时，该指令会注册为独立的、仅对子代理生效的系统提示词 section，而不会替换部署 persona 或改变委派的用户任务。推理强度仍是确切路由的不透明值，并通过作用域请求配置传入子代理模型调用。设置变化会重新注册工具，因此下一次模型请求会看到最新的枚举与说明。

提供商和模型标识符保持不透明。配置阶段没有内置提供商白名单；如果路由不可用，子代理 LLM 运行时会在实际请求时报告错误。推理强度遵循[适配器自有的确切路由能力](../architecture/2026-07-24-adapter-owned-reasoning-effort-capabilities.md)，不支持的值会在提供方 I/O 前失败。`spawn` 与 `fork` 宣告支持路由、指令和推理强度；`dsh-sdk` 只宣告支持路由。固定的 ACP、Codex 与 Claude Code 后端不显示选择器；`dsh-sdk` 会省略需要它无法安装的指令或推理强度的配置。强制传入不支持的字段会失败，而不是被忽略。

可继续子代理的描述符持久化解析后的提供商/模型对、子代理系统指令和推理强度，而不是配置名称。因此，即使配置被重命名、修改或删除，子代理恢复时仍使用建立会话时的路由、指令与强度。

## 考虑过的替代方案

**只暴露原始提供商/模型字段。** 这与工作流 Agent 覆盖项一致，但部署方无法提供简洁的允许列表和任务说明。直接选择仍可通过显式设置开启，而不是作为默认接口。

**每个模型创建一个委派工具。** 独立工具可沿用现有组合，但会因路由选择而复制提示、调度和结果约定，并让每次用户修改都需要编辑组合。

**只允许实时模型目录中的配置。** 目录是建议信息，可能缺少私有、暂时离线或刚配置的适配器。持久化任意字符串可支持 RunInfra 等外部路由，而执行阶段仍是权威的路由检查。

**把配置指令前置到委派任务。** 任务前缀会把稳定的角色指引与调用方编写的工作混合，并在用户消息中重复。独立的子代理系统 section 可以保留二者区别，并与部署 persona 组合，而不是替换它。

**在可继续子代理上存储配置名称。** 恢复时再次解析名称会让一次无关的设置修改把既有会话切换到其他模型。持久化解析后的路由可以保持子代理身份与重放行为。

**让不支持的后端忽略路由选项。** 静默回退会让面向模型的选择器失真。能力标志使固定模型后端可以继续使用但不宣称不支持的选择，并让服务在提供方启动前拒绝其他调用方。

## 后果

- 用户可以在 Web GUI 中新增、编辑、重命名和删除用户层子代理模型配置，无需修改 Cordis 组合；部署默认配置可以覆盖，但不能在该页面重命名或删除。
- 具名配置是默认的受控接口；任意直接路由是持久化的显式开关。
- 配置修改会影响未来的委派 schema 与调用，但不会重定向或重写已有的可继续子代理。
- 可选指令会向每个使用该配置的子代理请求加入稳定文本，因此会消耗子代理上下文 token；可选强度会为确切子代理路由选择适配器自有推理行为。
- 自定义子代理后端通过宣告 `modelRoute` 支持路由，通过 `instruction` 支持配置指令，并通过 `reasoningEffort` 支持推理强度。
- 包测试与真实 Web 设置场景共同固定提供方能力、设置分层、条件工具 schema、路由持久化和 Web 编辑器行为。
